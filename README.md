## ⚡ Стратегия кэширования данных (Caching Strategy & Invalidation)

Управление серверным состоянием реализовано через библиотеку **TanStack Query v5** (`@tanstack/react-query`) с вынесением логики в кастомные хуки в `src/hooks/usePlanets.js`:

1. **Конфигурация QueryClient:**
   * `staleTime: 5 минут (1000 * 60 * 5)` — в течение 5 минут данные считаются актуальными. При переходе между страницами или вкладками повторные сетевые запросы не выполняются, данные отдаются мгновенно из памяти.
   * `gcTime: 15 минут (1000 * 60 * 15)` — неактивные данные сохраняются в оперативной памяти браузера в течение 15 минут до сборки мусора.
   * `refetchOnWindowFocus: false` — предотвращает избыточные сетевые запросы при смене фокуса окна.

2. **Структура Query Keys:**
   * `['planets', params]` — кэширует списки планет с привязкой ко всем параметрам строки поиска (`search`, `type`, `habitable`, `sortBy`, `sortOrder`, `page`). Каждая комбинация фильтров и страниц имеет независимый кэш.
   * `['planet', id]` — кэширует детальную карточку планеты по ее уникальному идентификатору.
   * `['planets', 'all']` — кэширует полный список объектов для аналитических срезов дашборда.

3. **Инвалидация данных (Cache Invalidation):**
   Кэш принудительно инвалидируется в следующих сценариях:
   * **Создание новой планеты:** в мутации `useCreatePlanetMutation` в колбэке `onSuccess` вызывается `queryClient.invalidateQueries({ queryKey: ['planets'] })`. Это помечает закэшированные списки устаревшими и автоматически инициирует фоновый перезапрос свежих данных.
   * **Сброс базы данных к дефолту:** в мутации `useResetPlanetsMutation` также вызывается инвалидация `['planets']`.

4. **Защита от состояния гонки (Race Condition Prevention):**
   TanStack Query автоматически отменяет предыдущие незавершенные запросы при быстрой смене фильтров пользователем, гарантируя, что старый ответ не перетрет актуальный результат.

## 🔐 Архитектура аутентификации (Firebase Authentication)

1. **Провайдеры входа:**
   * Регистрация и вход по **Email и Паролю** (`createUserWithEmailAndPassword`, `signInWithEmailAndPassword`).
   * Вход в 1 клик через **Google** (`signInWithPopup`).
2. **Контекст и хук (`AuthContext` & `useAuth`):**
   * Централизованное управление сессией пользователя через слушатель `onAuthStateChanged`.
   * Автоматическое сохранение сессии при перезагрузке страницы (Persistent Sessions).
   * Обработка состояний загрузки (`loading`) и локализованных ошибок Firebase.
3. **Защита маршрутов (`ProtectedRoute`):**
   * Маршрут `/profile` защищен компонентом-стражем. Неавторизованные пользователи автоматически перенаправляются на `/login` с сохранением целевого адреса в `location.state`.
4. **Безопасность:**
   * Ключи конфигурации Firebase вынесены в `.env.local` с префиксом `VITE_` и добавлены в `.gitignore`.
   * В репозитории предоставлен шаблон `.env.example`.

## 🛠 Таблица маршрутов (Routing Table)

| Маршрут | Доступ | Описание |
| :--- | :--- | :--- |
| `/` | Публичный | Главная страница CosmoDex |
| `/planets` | Публичный | Каталог экзопланет (кэширование, пагинация, фильтрация через URL) |
| `/planets/:id` | Публичный | Детальный научный паспорт объекта (кэш по ID) |
| `/dashboard` | Публичный | Аналитический дашборд со сводной статистикой |
| `/about` | Публичный | Информация о проекте и технологиях |
| `/login` | Гостевой | Авторизация (Email/пароль + вход через Google) |
| `/signup` | Гостевой | Регистрация нового исследователя с валидацией паролей |
| `/profile` | **Защищенный** | Профиль пользователя (вывод Email, UID и кнопка Logout) |
| `*` | Публичный | Страница ошибки 404 |

# Заполните ключи Firebase в .env.local
